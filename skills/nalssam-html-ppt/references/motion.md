# 움직임 값과 근거

엔진에 들어 있는 움직임이 왜 이 값인지 적어 둔다. 새 움직임을 더할 때도 이 표 안에서 고른다.

## 한도

| 무엇 | 값 | 근거 |
|---|---|---|
| 장 전환 | 0.3초, 페이드 하나. 0.5초를 넘기지 않는다 | 전환은 내용이 아니라 이음새다. 길면 기다리게 된다 |
| 차례 등장 간격 | 60ms. 전체가 0.8초 안에 끝나게 | 50~100ms 가 자연스럽고 300ms 를 넘으면 기다린다 |
| 글자 등장 | 글자당 45ms, 1초 안. 글자가 많으면 간격을 줄인다 | 다 나타나기 전엔 읽을 수 없다 |
| 숫자 올라가기 | 0.9초, 빠르게 출발해 천천히 멈춤 | |
| 반복 움직임 | 넣지 않는다 | 5초 넘게 움직이면 멈출 수 있어야 한다 (WCAG 2.2.2) |
| 깜빡임 | 넣지 않는다 | 1초에 3번 넘게 번쩍이지 않는다 (WCAG 2.3.1) |
| 움직임 줄이기 | 설정이 켜지면 모두 1ms 로 | WCAG 2.3.3 |

## 이징

Remotion Scenes(lifeprompt-team/remotion-scenes, MIT)의 공통 이징 값을 CSS 로 옮겼다.

| 변수 | 값 | 쓰임 |
|---|---|---|
| `--out` | `cubic-bezier(.16,1,.3,1)` | 기본. 등장·막대·선 |
| `--smooth` | `cubic-bezier(.4,0,.2,1)` | 페이드 전환 |
| `--over` | `cubic-bezier(.34,1.56,.64,1)` | `data-fx="pop"` 처럼 살짝 지나쳤다 돌아오는 것 |

쓰지 않고 남겨 둔 값(필요할 때만): 극적인 등장 `cubic-bezier(.6,.01,.05,.95)`, 딱 멈춤 `cubic-bezier(.075,.82,.165,1)`.

## 전환 네 가지

모두 `clip-path` 와 `opacity` 만 쓴다. 지난 장을 아래에 깔고 새 장이 위에서 드러난다.

| `data-tr` | 모양 | 쓸 곳 |
|---|---|---|
| (없음) | 페이드 | 본문 모든 장 |
| `wipe` | 왼쪽에서 닦아내기 | 간지 |
| `circle` | 가운데에서 원으로 퍼지기 | 실습·활동 시작 |
| `slice` | 사선으로 자르기 | 전·후 대비 |

한 덱에서 본문은 페이드 하나로 통일하고, 간지에 쓰는 전환도 한 가지로 맞춘다.

## 영상용 레이아웃에서 가져온 구도

Remotion Scenes 의 Layout·List 장면에서 발표 화면에 맞는 것만 옮겼다.

- **큰 글자와 작은 라벨의 대비**: 간지의 번호는 화면 밖으로 나갈 만큼 크고 옅게, 라벨은 작고 자간을 넓게.
- **강조색은 단어 하나에만**: 제목 두 줄 가운데 한 단어.
- **늦게 자라는 선**: 제목이 나온 뒤 4~6px 선이 따라 자란다(`.grow`).
- **주인공 먼저**: 큰 숫자·제목이 먼저, 보조 설명은 다음 단계에.
- **첫 줄만 진하게**: 번호 목록의 첫 번호만 키컬러, 나머지는 옅게.

영상용 값을 그대로 쓰지 않은 것: 목록 항목 간격 0.5초(영상은 혼자 흘러가지만 발표는 사람이 넘긴다 → 60ms 로 줄임), 흔들리며 춤추는 글자, 글리치·네온·입자 효과(읽기를 방해한다).
