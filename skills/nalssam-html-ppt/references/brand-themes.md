# 다른 브랜드 톤을 입히는 법

기본은 날쌤 테마다. 사용자가 "토스 느낌으로", "당근 톤으로"처럼 한국 서비스의 디자인 톤을 원할 때만 이 문서를 따른다.

## 어디서 가져오나

ko/design.md 카탈로그(getdesign.kr)가 한국 브랜드의 색·글꼴·간격·라운드·그림자·규칙을 브랜드당 `DESIGN.md` 한 장으로 공개한다. 기억으로 흉내 내지 말고 그 문서를 받아서 쓴다.

```bash
curl -fsSL --create-dirs -o ~/.cache/use-design-md/index.txt https://www.getdesign.kr/llms.txt
curl -fsSL --create-dirs -o ~/.cache/use-design-md/<slug>.md https://www.getdesign.kr/services/<slug>/llms.txt
```

- 색인에서 브랜드 이름·디자인 시스템 이름·슬러그를 모두 대조한다(당근 → `seed-design`, 구름 → `vapor-ui`).
- 카탈로그에 없는 브랜드는 없다고 알린다. 비슷한 색을 지어내지 않는다.
- 받은 파일은 끝까지 읽는다. 뒤쪽에 `Do's and Don'ts` 와 `Known Gaps` 가 있다.
- `use-design-md` 스킬이 설치돼 있으면 그 절차를 따른다(`npx skills add CaesiumY/ko-design-md`).

## 덱에 옮기는 법

값은 `starter.html` 맨 위 토큰에서만 바꾼다. 장 안에 색을 직접 적지 않는다.

| DESIGN.md | 덱 토큰 |
|---|---|
| 바탕·표면 색 | `--bg` · `--card` · `--paper` · `--zebra` |
| 글자 색(본문 / 보조) | `--ink` / `--sub` |
| 브랜드 대표 색 | `--key`, 아주 연한 단계는 `--key-soft` |
| 보조 강조 색(있을 때만) | `--point`. 없으면 `--key` 와 같은 값으로 둔다 |
| 테두리 색 | `--line` |
| 라운드 단계 | `--r` |
| 글꼴 | `--sans`. 다시 나눠 줄 수 없는 글꼴이면 문서가 정한 대체 글꼴을 쓴다 |

새 테마는 `[data-theme="이름"]{…}` 블록 하나로 더한다. 이름은 브랜드명이 아니라 쓰임새로 짓는다(`blue`, `warm` 처럼).

## 꼭 지킬 것

1. **Known Gaps 를 먼저 읽는다.** 대비가 낮다고 적힌 색 조합은 본문에 쓰지 않는다. 문서에 없는 값을 채웠으면 "제가 고른 값"이라고 알린다.
2. **Do's and Don'ts 는 그대로 따른다.** "카드에 그림자를 넣지 않는다", "한 화면에 강조색은 하나" 같은 규칙이다.
3. **브랜드 이름을 덱에 넣지 않는다.** 제목·바닥글·클래스 이름·토큰 이름에 브랜드명, 디자인 시스템 이름, 그쪽 토큰 접두사를 쓰지 않는다. 로고·서비스 고유 문구도 쓰지 않는다. 빌리는 것은 겉모습의 규칙뿐이다.
4. **날쌤 덱의 구조는 그대로 둔다.** 결론 제목, 한 장 한 메시지, 대본, 바닥글은 바꾸지 않는다. 바뀌는 것은 색·둥글기·글꼴이다.
5. **눈으로 확인한다.** 바꾼 뒤 `check.js` 로 전체를 캡처해 대비와 강조색 넓이를 본다.

색 값은 카탈로그가 OKLCH 로 적는다. CSS 에 `oklch()` 를 그대로 써도 된다.
